# ひとりで回すパイロット手順

## この手順で何が言えるか

**言えること（仮説 H1・H2）**

* 同一アルゴリズム・同一初期値でも、異なるインタラクション履歴を経験した個体は
  異なる Behavioral Signature を形成する
* 同一個体の Signature は測定セッション間で一貫する

これはシステムの性質についての主張なので、**必要なのは参加者の人数ではなく個体数と履歴の種類**です。
ひとりで実施しても、システム評価としてそのまま使えるデータになります。

**言えないこと（仮説 H3・H4）**

* 人が自分のペットを識別できるか、個体性をどう評価するか

これは人間の知覚についての主張なので、参加者なしには何も言えません。
さらに自分を被験者にすると、どちらをどう育てたか・アルゴリズム・パラメータを
すべて知っている状態になり、識別できるのは当然で証拠になりません。ここは代替が効きません。

**このパイロットの実際の価値は 3 つ**です。H1・H2 の実機データが取れること、
本実験に必要な人数を決めるための効果量が推定できること、そして人を呼ぶ前に
パラメータの問題を潰せることです。3 番目が特に大きい。現在の定数では
`approach_player` が支配的になる兆候があり、この状態で被験者実験をすると
「べったりくっつく犬」と「離れていく犬」の 2 種類しかなく、
識別が簡単すぎるか不自然すぎるかのどちらかになりかねません。

---

## 準備

1. ワールドを新規作成（クリエイティブ、チート有効）
2. `/difficulty normal` — peaceful だと敵が湧かず、防衛や退避のイベントが一切発生しない
3. `/gamerule doDaylightCycle true`
4. 自分を operator にする（シングルプレイならチート有効で自動）
5. `/wolfai mode adaptive` で条件を確認

記録用に、セッションごとの日時・実施内容をメモしておくこと。
ログの `worldTime` と突き合わせるときに必要になります。

## 個体の用意

```
/give @s minecraft:bone 64
/summon minecraft:wolf ~3 ~ ~
/summon minecraft:wolf ~-3 ~ ~
```

2 匹をテイムします。テイム直後に **`/wolfai list`** で 2 匹の UUID を記録してください。
どちらを Wolf A（一緒に過ごす）、Wolf B（単独探索）にするか決めて、UUID とともにメモします。

**両者の初期状態が同一であることを確認します。**

```
/wolfai signature baseline
```

Wolf A の近くで実行 → Wolf B の近くへ移動して実行。
この時点で 2 つの Signature はほぼ一致するはずです。
**一致しなければ、個体差の源が経験以外にあることになり、研究の前提が崩れます。**
ここは必ず確認してください。

## 育成フェーズ

### Wolf A — 一緒に過ごす

* **撫でる**：しゃがんで素手で右クリック。10 秒のクールダウンがあるので連打は効きません。
  1 セッションで 15〜20 回を目安に
* **一緒に歩く**：Wolf A を連れて移動する
* **守る**：敵が出たら自分が倒す（`player_protected_wolf` が記録されます）
* **一緒に寝る**：近くでベッドに入る
* 生肉を与える（`feed`）

### Wolf B — 放っておく

* **座らせずに**、自分は遠くへ行く
* Wolf B が単独で探索する時間を作る（`safe_solo_exploration` が蓄積します）
* 撫でない、餌をやらない
* ときどき戻って、離れすぎて消えていないか確認する

**同じ場所に 2 匹を置いてはいけません。** Wolf A の近くで敵を倒すと、
Wolf B にも `player_protected_wolf` や `monster_encounter` が記録されてしまいます。
少なくとも 32 ブロック以上離してください（敵スキャン半径 16 ブロックの 2 倍）。

### 1 セッションの長さと回数

1 セッション 30〜45 分、合計 4〜6 セッションを目安にします。
シミュレーションでは 120 イベントで分離が出ました。撫でるのが 10 秒に 1 回なので、
撫でるだけでも 1 セッションで 15〜20 イベント貯まります。

**各セッションの終わりに必ず測定します。**

```
/wolfai signature session1
/wolfai signature session1
/wolfai export
```

`signature` を**同じラベルで 2 回**実行するのが重要です。セッション番号が
ワールド時刻から決まるため、2 回測ると別セッション扱いになり、
**個体内のばらつき（H2 の指標）が得られます**。1 回しか測らないと
個体内距離が計算できず、群間距離が意味のある差なのか判断できません。

Wolf A と Wolf B の両方で実行してください。

---

## 測定フェーズ

最終セッションの後、ラベルを変えて測ります。

```
/wolfai signature final
/wolfai signature final
```

両個体で実行したら、`/wolfai export` を実行してワールドを閉じます。

## 解析

```bash
cd analysis
pip install pandas numpy
python aiwolf_analysis.py "<ワールド>/aiwolf-research"
```

見るべき数値は `separation_summary.csv` の 3 つです。

| 指標 | 期待 | 意味 |
|---|---|---|
| `mean_within` | 小さい（0.1 未満） | 同一個体の指紋が安定している = H2 |
| `mean_between` | 大きい | 履歴の違う個体の指紋が離れている = H1 |
| `separation_ratio` | 2 以上 | 群間の差が個体内のばらつきより明確に大きい |

シミュレーションでは adaptive 条件で比 13、対照の static 条件で 1.1 でした。
`baseline` ラベルでは比が 1 付近であるべきです（育成前なので差がないのが正しい）。

あわせて `events_by_wolf.csv` で、**意図した履歴の違いが実際に記録されているか**を
確認してください。Wolf A に `pet` が並び、Wolf B に `safe_solo_exploration` が並んでいるはずです。
ここが意図と違っていたら、それはデータではなく運用の問題です。

## パイロットで判断すること

### 1. 分離が出るか

`final` ラベルで比が 2 を超えていれば、実機でも H1 が成り立っています。
超えなければ、育成量が足りないか、パラメータの調整が必要です。

### 2. 分布が極端すぎないか

**ここが一番重要な判断です。** `signatures.csv` を見て、
どちらかの個体で単一の行動が 0.6 を超えていないか確認してください。

超えている場合、その個体は「ほぼ 1 つの行動しかしない」状態です。
識別実験としては差が出すぎて簡単になり、かつ「生き物らしさ」を損ないます。
`AiWolfParameters` の次のいずれかで調整します（いずれも 1 行）。

| 調整 | 効果 |
|---|---|
| `SOFTMAX_TEMPERATURE` 0.6 → 1.0〜1.2 | 分布がなだらかになる |
| `StateImpactMatrix` の関係性状態の増分を半減 | 飽和までの育成時間が延びる |
| `PREFERENCE_LEARNING_RATE` 0.03 → 0.015 | 選好の成長が緩やかになる |

**調整したら `PARAMETER_SET_VERSION` をインクリメントし、パイロットをやり直してください。**
異なるパラメータで取ったデータを混ぜてはいけません。

### 3. 効果量の推定

`final` ラベルの `mean_between` と `mean_within` から、本実験で期待できる
差の大きさが見積もれます。これをもとに識別課題の正答率を予想し、
必要な参加者数を検定力分析で決めてください。
粗い目安として、3 択で正答率 70% を期待するなら 12〜15 人、
55% なら 30 人前後です（片側、α=0.05、検出力 0.8）。
**実際の設計では期待効果量を決めて正式に計算してください。**

## 本実験へ進む前に必要なこと

* **倫理審査** — 人を対象にするので必須。NAIST の手続きを早めに確認すること
* **参加者ごとの条件割り当て** — 現在 `/wolfai mode` はサーバ全体の既定条件を
  切り替えるコマンドなので、被験者間デザインでは割り当てミスが起きます。
  設定ファイルから参加者 ID ごとに決める仕組みが必要
* **撫で方の案内** — 「しゃがんで素手で右クリック」は誰も自力で気づきません。
  初回テイム時に 1 回だけ操作説明を出す実装が必要
* **識別課題の実装** — 複数個体を並べて選ばせる手続きそのもの
