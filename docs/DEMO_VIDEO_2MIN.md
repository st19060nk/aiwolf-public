# 研究紹介動画（1〜2 分・指導教員 / 研究室向け）の撮影計画

[`DEMO_RECORDING.md`](DEMO_RECORDING.md) のデモのうち、**研究の主張がいちばん直接見える 2 つ**だけを使って 1 本にまとめる計画です。
各デモの細かい操作・発火条件・数値の根拠は `DEMO_RECORDING.md` を参照してください。

## 動画で伝えること（1 文）

> **同じ初期状態のオオカミでも、プレイヤーとの経験によって行動の傾向が変わり、個体差が生まれる。**
> 行動を直接決めるコマンドはなく、変化はすべて実際の経験から生じる。

## 使う場面と理由

| 場面 | デモ | 理由 |
|---|---|---|
| ① 危険だった場所を覚えている | Demo C | 1 匹で 1 分以内に「経験 → 行動の変化」が見える。理由（参照された記憶・場所の恐怖）も画面に出るので、仕組みの説明になる |
| ② 同じ初期状態から別々の個体になる | Demo D | 研究の主張そのもの（経験から個体差が生じる）。最初に「2 匹が同じ」ことを見せられる |

Demo A（撫でて距離が縮まる）は変化が小さく時間がかかるので、2 分の動画では省きます（時間があれば ② の育成の早送りに含めます）。

## 構成（約 1 分 50 秒）

| 時間 | 映すもの | 画面で見せる数値 | ナレーション / テロップの例 |
|---|---|---|---|
| 0:00〜0:08 | タイトル | — | 「経験で行動が変わる AI ペット（Minecraft のオオカミ）」 |
| 0:08〜0:20 | 2 匹 A・B を並べ、`/wolfai inspect` を順に | State・Preference が **2 匹で同じ値** | 「研究用の初期状態。2 匹はまったく同じ」 |
| 0:20〜0:35 | （場面 ①）洞窟でオオカミが敵に攻撃される → 飼い主が倒す | `Memory: WOLF_DAMAGED`、`Loc fear` が上がる | 「この洞窟で危険な目にあう」 |
| 0:35〜0:42 | 洞窟から離れる（早送り） | `Loc fear` が 0 に戻る | 「離れて、しばらくしてから…」 |
| 0:42〜1:00 | 同じ洞窟に戻る | アクションバー **`Spatial memory activated Fear = 0.xx`**、サイドバーに **AVOID_LOCATION** | 「場所を覚えていて、避けようとする」 |
| 1:00〜1:15 | （場面 ②）育成の早送り：A は撫で・救援、B は離れて単独探索 | — | 「A は飼い主のそばで、B は一人で探索して 10 分ずつ過ごす」 |
| 1:15〜1:40 | 評価用の囲いの中：A は飼い主のそば、B は離れて探索 | サイドバーを A・B で切り替え（APPROACH / FOLLOW の P と EXPLORE の P） | 「同じ場所・同じ条件でも、ふるまいが違う（学習は止めて評価）」 |
| 1:40〜1:50 | `/wolfai summary`（または `/wolfai signature`）の結果を A・B で並べる | `last 5 min` の割合と平均距離。標準テスト（signature）のオフライン見積もりでは、平均距離 A 約 2 ブロック・B 約 39 ブロック | 「経験だけで個体差が生まれた」 |

**変化は行動そのものより、サイドバーの `P`（選択確率）で見せるのが確実です。** 行動は確率的に選ばれるので、
短い映像では偶然に左右されますが、`P` は状態と記憶から決まるのでぶれません（`DEMO_RECORDING.md`「表示の読み方」）。

## 撮影の段取り（合計 約 1 時間）

撮影は時系列どおりでなくて構いません。**Snapshot を使えば何度でも撮り直せます。**

| 順 | 作業 | 時間の目安 | 参照 |
|---|---|---|---|
| 1 | 撮影用の新しいワールドを作り、共通の準備をする | 5 分 | `DEMO_RECORDING.md` 0 章 |
| 2 | 2 匹をテイムして A・B と名付け、`demo reset` → `snapshot save initial` → `inspect` を撮る（0:08〜0:20） | 5 分 | Demo D「2 匹の用意」 |
| 3 | A を使って場面 ① を撮る。撮り終えたら `snapshot restore initial` で A を初期状態に戻す | 10〜15 分 | Demo C |
| 4 | A・B を 32 ブロック以上離して、並行して 10 分ずつ育成（画面を録画しておき、あとで早送り素材に使う）。終わったら両方 `snapshot save trained` | 10〜15 分 | Demo D「育成」 |
| 5 | 囲いの中で `evaluation start` → 5 分観察して撮る → `summary` | 10 分 | Demo D「Evaluation Arena」 |
| 6 | `/wolfai demo off` | — | |

場面 ① は A でなく 3 匹目のオオカミで撮っても構いません（その方が A の育成とは独立して撮り直せます）。

## 撮影時間を短くする

### 短縮版（推奨）：ゲーム内は場面 ① だけ、個体差はオフライン実験の図で示す（撮影 約 15 分）

時間がかかるのは場面 ② の育成（10 分 × 2 匹）と評価（5 分）です。個体差は、すでにオフラインの数値実験で
同じパラメータのまま測ってあり、図があります（[`figures/2026-11-14/fig3_within_between_30min_delay60.svg`](figures/2026-11-14/fig3_within_between_30min_delay60.svg)、
`./gradlew individuality` で再現可能）。そこで ② は撮らずに、この図で示します。

| 時間 | 映すもの |
|---|---|
| 0:00〜0:08 | タイトル |
| 0:08〜0:15 | オオカミの `inspect`（研究の初期状態） |
| 0:15〜1:00 | 場面 ①（洞窟で攻撃される → 救援 → 離れる → 戻ると AVOID_LOCATION） |
| 1:00〜1:20 | Figure 3（個体差：同じ個体の中のばらつきより、個体どうしの差が大きい）。「オフラインの数値実験」と明記する |

撮影の作業は「共通の準備（5 分）→ 1 匹テイム → Demo C（10 分）」だけです。

### 場面 ② も撮る場合：待ち時間を `/tick` で縮める

研究 AI の判断・記憶・クールダウンはすべて**ゲームの tick** で数えています（実時間は記録用の時刻にしか使っていません）。
そのため Minecraft 1.21 の `/tick rate` でゲームを速く進めても、パラメータを変えずに同じ経験・同じ判断が速く進むだけです。

```
/tick rate 60      ← 3 倍速（育成のうち、B を一人で探索させて待つ区間など）
/tick rate 20      ← 元に戻す（撮影する区間・自分で操作する区間は必ず 20 に戻す）
```

* プレイヤーの動きも速くなるので、撫でたり戦ったりする区間では使わず、**待つだけの区間**に使います。
* 速くした区間は動画では早送りとして見せるので、そのまま使えます。
* これで育成は 10 分 → 4〜5 分程度になります（撫での 10 秒のクールダウンも tick なので、3 倍速なら約 3 秒）。

## 録画の設定（NVIDIA App / GeForce Experience）

* **Alt+Z** でオーバーレイを開き、録画の設定を 1920×1080・60 fps・高画質にする（保存は mp4 なので変換は不要）
* **Alt+F9** で録画の開始・停止
* **インスタントリプレイ（Alt+Shift+F10 で ON、Alt+F10 で直前の数分を保存）** を ON にしておくと、
  AVOID_LOCATION が出た瞬間などを撮り逃しても、あとから保存できる
* 開発用クライアント（`./gradlew runClient`）は Java のウィンドウなので、ゲームとして認識されないことがある。
  その場合は Minecraft を **F11 で全画面**にするか、オーバーレイの設定 → プライバシー管理で **デスクトップキャプチャ** を ON にする
* マイクはオフ（ナレーションはあとで入れる）。保存先は既定でユーザーの「ビデオ」フォルダ

## Minecraft 側の設定

* `/wolfai debug detailed` でサイドバーを出す。**GUI の大きさ**（設定 → ビデオ設定 → GUI の大きさ）を 3 程度にすると、動画でサイドバーの文字が読める
* **F3（デバッグ画面）は出さない**（座標などが映り込む）。**F1 は使わない**（サイドバーも消える）
* 視野角（FOV）は 70〜80 程度にすると、オオカミとの距離感が伝わりやすい
* 昼に固定する（`/gamerule doDaylightCycle false`）。敵は昼でも燃えない `husk` を使う
* 画面に出るのはオオカミの名前と匿名の ID だけで、生の UUID は出ません。プレイヤー名はチャット欄に出ることがあるので、気になる場合は編集でぼかす

## 注意

* 撮影用のワールドは本実験のワールドと分けてください（Demo Mode のログは `demo/` に分かれますが、個体の状態はワールドに残ります）。
* 撮影のために研究パラメータを変えないでください。変化が小さく見える場合は、経験の量（育成の時間・被弾の回数）で調整します。
